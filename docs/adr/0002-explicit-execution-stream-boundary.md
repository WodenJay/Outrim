# 显式执行按输出流复用处理核心

`outrim exec [--no-compress] [--timeout-ms <ms>] -- <program> [args...]` 只执行一次目标程序，不把参数重新拼成 Shell 脚本。捕获模式并发排空 stdout、stderr，命令结束后把每条非空、完整的 UTF-8 文本流分别交给共享的 `execution::Execution`；原文保存、恢复跳过、最终提示成本、收益和诊断沿用已有核心，不在进程模块复制策略。按流计样本而非按进程计数，因为两条流可能命中不同规则；缺少会话或工具调用上下文时保留空值，不能用执行单元 ID 冒充会话。

`execution::Context` 允许后续宿主提供真实来源、会话、工具调用和记录设置快照；`command::source` 对 argv 共享已知搜索、路径和日志命令形式，日志取舍遵循 [ADR 0001](0001-prefer-conservative-log-classification.md)。CLI 在启动前快照已有记录开关，每次执行分配独立单元 ID；诊断事件的可选 `execution` 字段关联单元与输出流，旧记录无此字段仍可读取。`gain --detail` 展示执行单元、流及事件路径；关闭记录不影响已保存原文和收益。

单流最多捕获 8 MiB；越界时先转发已捕获前缀，再持续转发余下字节。非 UTF-8 或含非文本控制字节的输出完整返回，不做有损解码。越界和非文本流只在记录开启时写不含内容、无字符量的诊断原因，不伪装成处理样本。主动 `--no-compress` 则从一开始继承三个标准流，不捕获、不建执行处理上下文、不保存内容或未测量的字符量。

Unix 使用独立进程组并在需要时移交、恢复终端前台组；取消和超时先发信号，再清理剩余组成员。Windows 在恢复挂起进程前绑定 kill-on-close Job Object，以阻止后代在绑定前逃逸。两种模式均管理进程生命周期，正常结束也清理仍持有输出管道的后代；不会承诺清理主动脱离 Unix 进程组的守护进程。持久化或诊断不可用时返回原文或忽略记录错误，不能重跑目标程序或替换其退出状态。
